## 構成・採算への反映

現行利用量は小さく、待機固定費の確認価値が高い。一方、この実績だけで100〜1,000社の性能・原価を保証できない。既存モデルの利用頻度、scan性能改善率、SQL配賦、東京単価補正、為替は仮定のまま維持し、実測で置換しない。PR #2のExcelは変更していない。

初期10社はVM常時稼働への置換を即断せず、既存Cloud Run/GCSと機能を再利用する方針を維持する。専用プロジェクト・DB分離の費用と、scan待機削減の改善幅は分けて比較する。min=0・非同期・常駐clamdはコールドスタート、定義更新、通知再試行、処理保証の検証と追加開発を要し、今回実装しない。

## 残る取得項目・ユーザー操作

1. Google Cloud Consoleの請求で、対象プロジェクトmsp-zabbixを絞り、2026年7〜9月の月別費用をCSV取得する。可能なら10月途中も別取得。サービス/SKU、使用量/単位、費用、割引・クレジット、通貨、対象期間を含める。Cloud Runはサービス別、Storageはバケット別に分解できる範囲で取得する。分解できない費用は共有のまま保持する。取引先名・支払情報は不要。
2. 請求閲覧できない場合は請求先アカウントのBilling Account Viewer（または管理者によるCSV出力）が必要。既存BigQuery請求エクスポートがある場合のみ、dataset閲覧・ジョブ実行権限を別途確認する。新規エクスポートやIAM変更は今回行わない。
3. DB管理者が対象DBにて既存 `cost-analysis-aggregate-readonly.sql` をレビュー後に実行し、匿名集計結果のみ共有する。BEGIN READ ONLYとROLLBACKを含む。ファイル名・メール・トークン・OTPを取得しない。送信/ファイル件数、サイズ分布、記録済みOTP、scan経過時間を確認する。サイズは申告値、scan経過は待ち時間を含み、純粋なスキャン時間ではない。
4. SMTP外部料金、共有SQL配賦、バックアップ実使用量、実削除/平均保持期間、同時実行ピーク、ClamAV定義更新・大容量性能は未確認。追加ベンチや運用変更は別途承認対象。
